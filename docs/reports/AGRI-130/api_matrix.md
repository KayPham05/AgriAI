# AGRI-130 — Endpoint matrix

## Manifest mechanism

The JSON manifest is an independently authored inventory of **35 method/route pairs**, including both audit-log aliases. It is not generated from the runtime route table. Each entry names applicable behavioral cases through stable `ApiCase` traits.

- Runtime guard compares the complete controller endpoint set with the manifest; missing, extra or duplicate routes fail. Route casing and leading/trailing slashes are normalized; constrained route parameters are retained.
- Mapping guard resolves each case ID to exactly one discoverable xUnit Fact/Theory method. Missing references, duplicate IDs, unmapped cases, non-tests and empty route mappings fail. One case may cover several routes; one theory may execute several data rows.
- Four negative mapping scenarios exercise the guard itself. Guard success establishes inventory consistency; HTTP assertions and successful TRX results separately establish execution.
- The table below is generated from the authored JSON. Source edits must update the manifest and applicable tests together; changing a label cannot make an incorrect HTTP assertion pass.
